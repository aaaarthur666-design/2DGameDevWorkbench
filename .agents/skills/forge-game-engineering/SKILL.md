## Establish the project contract

Identify the target game directory and the reference CopyWorms checkout separately. Locate `project.godot`, the current architecture report, instructions, scenes, configs and affected scripts. Keep the reference checkout read-only unless it is explicitly the requested edit target. The source URL and verified baseline are in [CopyWorms contracts and reuse](references/copyworms.md); do not hard-code a user's drive path or assume the old report matches newer code. Use `scripts/inspect_source.py ROOT` to inventory the relevant files and current hashes without starting Godot. If only documentation is available, design from that evidence and identify unverified code rather than claiming a tested transplant.

Use the project's working architecture as the starting point: formal bases and config resources, scene/UI Builders, explicit global contracts and level lifecycle. Do not replace it with a generic game framework. Inspect dependencies before choosing what to retain, adapt or omit. Read [CopyWorms contracts and reuse](references/copyworms.md) for architecture and code work.

Namespacing and missing dependencies remain explicit. These scripts do not call a provider, create workbench tasks or require API keys.

## Implement and verify the requested slice

For project creation, establish the requested playable slice and target directory; if missing, inspect available materials while asking only for those consequential choices. For an existing project, preserve the working scene paths, autoload ownership and gameplay timings. Resolve routine resource names and file placement yourself from the actual project. Do not import story, balance constants, unused managers or every CopyWorms module by default.

Produce a short source-to-target map: chosen assets and animation aliases, reused/adapted scripts and dependencies, scene ownership, state/event/config contracts, and unresolved inputs. Scale it to the task; do not manufacture paperwork for a one-clip replacement. Keep authored controller scripts outside generated resource folders so re-export cannot erase them.

Verify with **Godot 4.7.x**: resource import/parse, frame order/speed/loop, action switching without per-frame restart, repeated one-shots, facing/feet alignment, collision placement, and enter/exit/re-entry as applicable. Use an isolated project for helper/fixture tests. Run `npm run test:engineering` for helper changes, setting `GODOT_47_BIN` for actual 4.7.x execution; an absent engine is a reported skip, not a pass. `--headless --editor --import` alone is not playback or gameplay validation. If only another engine version is available, record that limitation rather than silently upgrading the target.

Deliver actual resources/scripts and a concise preview or project link, what ran, and a task-specific manual check. Distinguish code written, assets staged, engine-tested, visually checked and full-game acceptance. No claims of target-engine or WorkBuddy behavioral validation from a static report or from the workbench asset viewer alone.

## Evaluating edited art

Real image quality reports and provider usage evidence do not prove engine acceptance. After a generated edit, preserve its new task/hash and inspect silhouette, anchor and collision fit before replacing game art. A raw model response may change pixels outside its mask; do not silently bind edited pixels under the original generation hash. Keep evaluation variants separate from an already accepted scene until adoption is explicitly requested.

New image-assets masked deliveries locally restore all mask-alpha>0 source RGBA8 pixels and verify the saved PNG. Raw provider output may still drift; use the delivered image hash and processingEvidence. process-image performs the same repair on existing candidates without generation. Alpha1 cleanup preserves higher-alpha edges and never alters masked protected pixels; a separately cleaned baseline has its own task/hash. These guarantees cover protected pixel identity, not the edited region's shape, seam quality or collision fit. Preserve source/derivative provenance during asset adoption and export.

For a requested local repair of an existing saved source, follow [local image editing](../../../docs/image-editing.md) through the production Skill. The five registered tools are workbench_inspect_image_target, workbench_resolve_image_region, workbench_edit_image_region, workbench_apply_image_candidate and workbench_get_image_edit; the first four form the edit/adopt workflow, and get-edit reads its saved session. 7A is local-only and does not generate art or bypass manual map production, stitching or expansion. All image-* calls, including refresh reads, use one canonical Bridge per data directory with no direct-write fallback. Preserve durable commandId, source/version CAS and explicit candidate parent; unknown submission is not permission to resubmit. Keep original PNG/JPEG/WebP file sha256 separate from decoded sRGB/RGBA8 straight-alpha rgbaSha256.

7B implements a shared local workspace for map single images, interactable default static images and independent image-task variants; actual UI adoption acceptance is recorded separately. Map/interactable hosts first flush durable saves, suspend cross-editing/navigation, then read the exact adopted version and update the local save baseline. Source view is the frozen session source; candidate view can contain unsaved strokes. Browser IndexedDB pixel drafts are bounded, delayed local recovery copies, not server candidates or cross-browser backups. Continue after adoption by creating a session from the current target.

restore-region samples source or completed candidates within the same source-version session. Applying candidateVersion=source restores the session's original pixels as a new version of only the bound image, using current guards and a known image binding; preserve other images, geometry, behavior and unrelated visual parameters. Default static-image adoption still clears idle/focus animation selection. Do not roll back an entire project to restore one image, or resubmit a new command because the server adopted but the host refresh failed.

7C AI editing is available through the production workflow when explicitly requested. Mask add/subtract brushes edit hard mask-runs, not RGBA; inspect the actual scope before submission. Base candidate, region, prompt and reference bytes are frozen, and interrupted requests retain the same command/task identity without automatic model retries. Protected pixels are locally restored and verified. Optional preserveAlpha=true also copies every Alpha byte from the selected edit base, skips cleanup and verifies the saved PNG; the UI defaults on, while API callers request it explicitly. Confirm alphaPreservation evidence and still review internal texture, seams and collision fit. Saved previews switch directly to verified image bytes when restoring. Creating a session or selecting a candidate updates imageEdit/imageCandidate while retaining host parameters. These links reopen the requested session/candidate; invalid current guards allow history inspection without writing. 7D supports exact static state slots and scene references. A scene-instance target derives a material and rebinds only that instance; other instances sharing its old material remain unchanged. A scene-layer target is writable only after verifying a single-source identity mapping against the embedded Forge or Pixelwork v2 ZIP for every scene map layer, including hidden layers and layers excluded from export. Both the selected scene-layer lock and source image-type lock apply. Missing, damaged or inconsistent source packages remain read-only; a source-editor entry does not repair a missing package. The displayed PNG and embedded ZIP commit together. Derived, multi-tile, feathered or unmapped layers remain read-only with a source-editor entry. Do not silently replace upstream projects or other instances. An edited source does not automatically replace a pinned scene or installed game resource. Consume the exact adopted/exported version through the authorized delivery flow. Keep call counts and acceptance results dated; mock success, pixel protection and file installation do not prove fresh model quality or Godot execution.
