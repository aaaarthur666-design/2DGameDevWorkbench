# 最新地面攻击的外形与动作退化复盘

本次按用户补充，将“武器形态一致、人物形态一致、动作符合预期、流畅”共同作为对照标准。最流畅的样本是 `20260907_player_cyber_attack_003`，已知问题是换手；用户认可它的武器、人物形态和动作表现，不应只保留节奏方面的经验。

## 最新任务实际发生了什么

任务 `20260907_edited_71d4d1a0a4674ad499799bf548302764_v1_attack_002` 确实运行了 version 4 的 4+8+4 三段计划，原始返回为 5+9+5，最终输出 16 帧。视觉检查协议是 version 5，已实际调用两次混元，未通过检查。本次排查仅读取这些已有结果，没有重新调用服务。

逐段原始画面显示：
- 蓄力末尾的刀主要竖在身体侧后方，未形成成功样本中清楚的肩后引刀姿态。
- 出刀段第 2–4 张原始图开始出现更宽的胸甲与躯干；后段刀刃退化为短亮块、分离碎片，动作也偏离预期的纵向劈砍。
- 收招段才重新接收到原始参考图，最后回到原型。末帧正确不能证明中间人物和武器没有变化。
- 原始图里已存在上述问题。此前整理帧数还把蓄力段原始第 4 张删掉了，保留了作为上下文的第 1 张；这可能进一步削弱过渡，不能靠凑齐 16 帧代表动作质量。

## 与成功样本的关键差别

成功样本用两段请求。在最关键的“出刀到收招”生成期间，同时提供真实蓄力末帧作为起点、原始角色图作为终点。模型在整个后段都能直接看到原型的身体、盔甲和刀。

三段版的出刀请求只有上一段生成图，原始角色只存在于文字描述中；直到第三段收招才重新提供原图。形态变化因而可能从蓄力末帧向后传递，在长出刀段继续扩大，再在收招时被拉回。原图终点是明确丢失过的视觉约束；这是一项有请求记录支撑的退化因素，但尚不能证明它单独决定了全部质量变化。

新版还加入了肩、肘、腕“必须运动”等较强指令，以及可能误伤正常刀光的特效限制。这些与成功样本的简短动作要求不同，本次一并收敛到自然动作和完整实心刀刃。

## 本轮修正

- 新地面攻击计划为 version 5：4 帧准备 + 12 帧连续出刀/随挥/收招。后段从真实蓄力末帧开始，始终提供当前原图作为终点和外形参考。4/8/4 仍是节奏目标，但没有声称已识别或强制实现每个动作阶段。
- 保留同一物理持刀手约束，恢复直接、连贯的劈砍指令，去掉“各关节必须运动”的强迫要求。明确允许贴合刀刃运动的连续弧光，同时要求实心刀刃清楚。
- 新地面计划只移除额外返回且与输入图几乎相同的上下文帧。若它是不同的姿势，则保留并如实显示实际帧数；不再为凑帧数删除中间过渡图。所有原始帧与来源映射保留。
- 视觉协议 version 6 增加独立的人物与武器外形核查。初检没有提出外形问题时，复核仍必须检查全部实际帧，允许发现新的外形问题。确认需要原图特征、相邻帧证据和足够置信度；透视变化、遮挡和正常拖尾不直接算武器变形。
- 外形与武器任一项未取得充分证据，不能显示总体通过；确认的问题自动定位到逐帧修补。仍由人决定是否生成，不自动补做。
- 空中攻击继续使用原三段计划，避免把地面站立原图强制当作空中终点；独立外形检查对地面和空中都生效。旧 version 1–4 任务的保存计划与原素材不改写。

默认 128×128 地面候选固定两次 PixelLab 请求，预计 1+3=4 个 generation 额度；视觉仍最多两次。本轮没有新的付费生成、视觉调用，也没有启动此前用户拒绝的实测。

本轮恢复的是成功样本中“连续出刀收招、起终点双图参考”的关键结构，并保留用户的短蓄力目标；它并非完整复刻旧样本的 8+8 请求。实际成功率与图像质量不能由代码测试证明，尚未再次实测。

本轮验证：独立 harness 完整测试 408 项、工作台组件完整测试 426 项通过（各含额外 63 项子测试）；最终改动的 83 项专项回归通过。浏览器确认工作台新地面任务显示两段生成与原图终点提示，空中任务仍为三段。16 个原任务记录和 73 张已保存分段原始帧校验无变化。上述检查验证流程与数据保护，不代表已验证新生成图像质量。
