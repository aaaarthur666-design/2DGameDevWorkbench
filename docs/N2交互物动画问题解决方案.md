# N2 交互物动画问题：解决方案

> 状态：方案，待审核，**尚未执行**（2026-11-11）。分支 `paper-vbyc`。
> 针对《[N2 前置小测问题报告](N2交互物动画问题报告.md)》。样例见 [`examples/n2-pilot-20261110/`](../examples/n2-pilot-20261110/)。
> 本文的帧级观察来自一名评审（起草本文的 Agent）对归档帧的复看，没有第二评审，也没有新的生成。

## 1. 结论

1. 小测的 1/8 说明的是"不经工具的一次生成不可靠"，不是"方法对交互物无效"。小测直接调用生成接口，没有经过规划、结构解析、分段复核和人工采用。
2. 报告提出的大部分能力，工具里已经有，但对交互物没有生效：语义分割只对角色开放，专家提示与合同是为角色写的，物品图移送入口关闭。
3. 进入条件形成了死循环：物品图移送（N2）要等小测通过才开放，而小测因为移送没开放，只能绕过工具。
4. 解决方向是**让已有的核对能力对交互物生效，再用完整流程重测**。不新增核对能力，不做部件分层与轴点变换。
5. 生成器本身的成功率，在我们这一层改善不了，也不需要改善。方法的主张是错误不往后传、能用的部分被确认下来。

## 3. 工具里已经有什么

| 报告要求的能力 | 现有实现 | 对交互物是否生效 |
| --- | --- | --- |
| 生成前把要求与实际参考图核对 | 外观、动作两位专家先独立观察参考图，再由策略专家和协调者写合同，每条要求标注来源（`collaboration/planning.py`） | 流程能跑，但提问方式面向角色 |
| 知道哪个部件动、哪个不动 | 结构解析：本地 SAM 2.1 加一次语义调用，得到部件、锚点与关系（`structures.py`、`structure_parser.py`） | **否。** `structures.py:67` 固定按角色类型加载；前端结构面板对交互物不显示（`motion-temporal-structure.tsx:127`） |
| 在实际帧上看部件是否保持 | 时序追踪（`tracking*.py`） | 否，依赖结构解析 |
| 目标首次到达与最终停留分开 | 分段确认时可选"提前到达的姿势"作为真实锚点，其后的尾帧被排除并记录（`checkpoints.py` 的 `selected_anchor_frame`、`excluded_tail`） | 机制与对象类型无关，可直接用 |
| 给出有证据的质量结论 | 两次基础检查、外观与运动两位独立专家、至多一次争议复核、可见性核对；矛盾保留给人工（`production_review.py`、`independent_review.py`、`dispute_review.py`、`visibility_review.py`） | 流程能跑，判据面向角色 |
| 相邻帧变化线索 | 近静止提示（`motion_evidence.py`） | 可直接用；只提示停顿，不查透明度突变 |
| 按运动幅度定帧数 | 规划专家决定每段 4–16 帧（`planning.py`） | 可直接用。小测固定 16 帧，没有经过规划 |
| 可选末帧条件 | 提供方适配器支持 `last_frame`（`providers/pixellab.py:282`） | 可直接用。小测未使用 |
| 段内修复 | 外观编辑（128 像素一次 2 帧）、过渡重画（`repairs.py`） | 可直接用 |

## 4. 为什么这些能力在小测里没起作用

1. **小测绕过了整条流程。** 帧数、起始图提示词和动作文字都是手写的，直接提交给生成接口，结果由一个 Agent 评定。报告"能够归因到哪一层"一节已写明这一点。
2. **结构解析对交互物关闭。** 这是做对象抽象（N1）时有意收窄的：角色结构只对角色显示。
3. **合同与专家提示面向角色。** 质量维度固定为"完整、装备、节奏"（`contracts.py:74`），运动约束是"支撑、发力"（`contracts.py:124–125`）。没有"运动部件、固定部件、允许的运动方式、终态"这些字段。专家系统能运行，但问的不是交互物该问的问题。
4. **移送入口关闭。** 物品原图不能成为动画参考（`lib/workbench/adapters/reference-art.mjs`），交互物无法进入开放动作流程。
5. **进入条件设错了对象。** 原条件要求"原始序列直接通过"，等于要求论文实验中的对照组过关。

## 5. 方案

### 5.1 要做的

| 编号 | 内容 | 说明 | 与执行计划的关系 |
| --- | --- | --- | --- |
| S1 | 物品图移送以实验开关方式打开 | 默认关闭，只在显式启用时允许 128 像素 PixelLab 物品图成为动画参考。让交互物能走完整流程，同时不向普通使用者承诺效果 | N2 的一部分提前，但不作为正式入口 |
| S2 | 结构解析对交互物开放 | 去掉 `structures.py` 中固定的角色类型；前端结构面板对交互物显示。语义调用的提示改为按对象类型取词 | 新增，原计划没有 |
| S3 | 交互物合同模板 | 合同增加：A 状态与目标状态的描述、运动部件、固定部件、运动类型、终点与停留要求。质量维度按对象类型切换。规划与复核专家的提示按对象类型切换 | 即 N3，提前到 N2 之前 |
| S4 | 起始图核对成为交互物的固定步骤 | 规划阶段明确输出"参考图是否满足任务前提"：视角、初始状态、部件归属是否有歧义。不满足时停在规划，不提交动画 | N3 的一部分 |
| S5 | 透明度突变检查 | 在近静止提示旁增加一项确定性线索：固定区域或应保持不透明的区域，逐帧比较 Alpha。只作线索，结论仍由复核给出 | 新增，很小 |
| S6 | 分开给结论 | 复核分别输出"状态帧可用""过渡可用""固定内容保持"。状态帧可用而过渡有缺陷时，状态帧仍可确认为检查点，过渡单独进入修复 | N3、N4 的一部分 |
| S7 | 运动类型与不支持声明 | 合同中的运动类型取：外观变化、铰接转动、形变、带遮挡的刚体平移。最后一类在规划阶段标为"当前生成器不适合"，由使用者决定是否仍要尝试 | 新增 |

停留的实现沿用现有规则：不由模型画，由确认过的真实帧在播放层重复。这与规划提示里"不自动倒放、补帧或替换"的规定一致，因为重复的是已确认的真实帧，没有新造内容。

### 5.2 不做的

| 内容 | 原因 |
| --- | --- |
| 报告建议的第 4 项：部件分层、轴点变换、受限区域合成 | 会把工具变成骨骼绑定式的动画工具，依赖可靠的部件分割，工作量大，且与"编排黑盒生成器"的论文主张不是一回事。带遮挡的刚体平移按 S7 标为不支持，写入论文局限 |
| 靠改提示词让模型遵守约束 | 没有证据有效，且是针对样例的调参 |
| 返工修补这 8 条样例 | 对工具和论文都没有增益。这 8 条原样保留，作为"不经工具的一次生成"的失败记录 |
| 用局部调整的区域平移确定性地做出栅门的每一帧 | 等于不经生成造出目标状态，与已定的"B 状态由生成得到并经验证"不一致 |

### 5.3 顺序与进入条件的调整

原顺序：小测通过 → N2 移送 → N3 合同 → N4 状态链。

新顺序：

1. S2、S3、S4、S5、S6、S7（结构开放、合同模板、核对与结论拆分）。全部用模拟提供方和现有 8 条归档序列做回归，不产生费用。
2. S1（实验开关）。
3. **第二轮小测：经过完整流程。** 沿用同样的四种物品，起始图允许因 S4 的核对而重做。
4. 按新进入条件决定是否把移送转为正式入口，再做 N4 状态链和 N5 写回。

新进入条件（建议，数值待你确认）：

- 判定对象是"套用方法后的结果"，即是否得到了确认的状态帧和可用的过渡，而不是原始序列是否直接通过。
- 同时记录原始序列的通过情况，作为对照。
- 栅门这类被 S7 标为不支持的物品，不计入分母，单独报告。

## 6. 对论文的影响

- 现有 1/8 可以直接使用：它是交互物上"一次生成、不检查"这一对照条件的首批记录，对应失败刻画（RQ1）。需注明每种物品只有一张起始图、两个种子、单一评审。
- 交互物部分的说法收窄为：方法能拦住错误状态，并在部分运动类型上得到可用的状态与过渡。带遮挡的刚体平移写入局限，栅门是其证据。
- 若第二轮小测后可用结果仍然很少，交互物只作为失败刻画和局限来写，主实验仍是角色长动作。这不影响论文主张成立。

## 7. 没有验证的事项

- SAM 2.1 对 128 像素物品图的分割质量。此前只在角色上验收过。
- 多专家复核对机械类物品的判断是否可靠，是否能发现指示灯的单帧闪空、拉杆的越位。
- 末帧条件能否纠正中间轨迹。
- 帧数减少后是否不再越位。
- 第 2 节的复看只由一名评审完成；"拉杆与指示灯大概率可挽回"是估计，没有按正式流程评定。
- 方法提高的是被采用结果的正确性，不提高生成的成功率。交互物上得到一个可用状态需要多少次生成、多少人工，目前没有数据。
