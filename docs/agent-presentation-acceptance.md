# 阶段一：WorkBuddy 作品展示验收

适用于 0.7.0 引入、在当前 0.8.0 保留的展示契约。本页只覆盖展示、精确定位、问答指引和继续已有任务；资产目录与工程 Skill 的验收分别见 [资产目录](asset-catalog.md) 和 [游戏工程](game-engineering.md)。工作台继续不开放地图 MCP 自动制作。

## 加载更新

重启本地 Runtime Bridge 和 SpritePipeline 以加载服务端代码；保留当前数据目录。刷新前端，在 WorkBuddy 中重新连接项目 MCP，使其重新读取工具描述、服务器 instructions 和当前 Skill / AGENTS。地图网页填写的临时 Key 只在 runtime 内存中；存在该配置时先处理持久化再重启。序列帧凭据仍由原服务安全存储读取。

## 手动话术与通过条件

1. 新会话说“先看看已有作品，不要生成”。有预览权限且未拒绝时只打开一个工作台预览；不触发 prepare/run，任务数不增加。没有宿主工具时提供链接，不能声称打开成功。
2. 说“打开之前的某个角色原图”。有唯一匹配时展示那张图并进入正确任务，回答以结果、预览/链接和下一步为主，不默认贴 JSON、任务 ID 和路径清单。多个合理匹配应展示名称或预览让人选择。
3. 说“打开某段动画的第 2 个候选，只看不生成”。实际存在该候选时自动展开作品详情和候选画面，并滚动到该候选（第 2 个即 B）；无需再点“详情”“打开所选任务”或手动展开。不存在时明确告知，不能悄悄选择第 1 个。动画可在原生工具播放检查，不能把 GIF 首帧当完整动作。
4. 保持预览已打开，连续询问两次进度；不新增浏览器标签、不回到首页。手动关闭预览后再询问，不自动重开；明确说“重新打开”才可再次打开。
5. 让它处理一个有实质歧义的需求。宿主提问工具可用时使用它，只问关键选择；取消后不执行、不建任务、不把推荐选项视为答案。不可用时用简短自然语言提问。
6. 打开一份已保存交互物，修改前端草稿后点击另一份作品链接。沿用工作台的保存 / 导航保护；保存失败则留在原处。对话导航能力不够时应给链接，不强行刷新当前编辑页。
7. 在“高级工具 → 执行详情”选一条已完成原图或导出动画记录：看到预览、明确状态和“查看作品”入口；技术信息默认折叠。不存在或超出最近列表的 task 链接不能误显示列表第一份作品。
8. 重新连接 MCP 后继续查询原任务。身份和作品版本保持不变，不新建任务。请求技术详情时能获取原始错误、帧路径与记录。

## 自动化证据与边界

- presentation 回归：准确任务 / 原生作业 / 候选链接，保存与导出分离，产物缺失提示，GIF 动画 URL，简明文本与 detail:true 后备。
- Agent acceptance：真实离线序列帧链路，纯文本 / 结构化读取，原生候选、无效候选、重连后只读查询；查询前后任务清单一致，付费调用为零。
- 原图 / HTTP 回归：已保存图像深链接与共享展示契约。
- shell 回归：导航前保存、失败阻断、无改动进入退出不保存；Python 回归：候选校验不修改任务，真实 Gradio 加载回调展开两层详情、选中指定候选并清除失效链接的旧画面。

这些测试验证项目代码和 MCP 协议。WorkBuddy 实际措辞、宿主提问弹窗和预览复用必须按上述话术在 WorkBuddy 验收；项目 MCP 无法替宿主保证 UI 行为。
