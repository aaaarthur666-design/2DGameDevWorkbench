# 地图拼接编辑器

主入口为 `/tools/map-stitcher`，使用 FrameRonin / Pixelwork v2 数据模型。旧版保留在 `/tools/map-stitcher-legacy`。Unity 功能不在本工具范围内。

## 开始编辑

运行 `npm run dev:interactable` 可以启动网页和 Runtime Bridge，且不启动序列帧服务；完整工作台使用 `npm run dev`。访问 `http://localhost:3000/tools/map-stitcher`。

1. “新建 / 导入”将第一张图片作为中心地图，按顺序填入首圈卡片。PNG、JPEG、JFIF、WebP 单张上限 30 MB。新建前先保存当前地图。
2. 单击地图块标签选择卡片。“地图块”页签的上传替换当前图片；多张图片继续填入同视图的空卡片。拖入画布时会提示目标卡片和视图。
3. 使用 4 / 8 / 12 分扩展卡片，设置横纵重叠比例，从所选卡片继续向外扩展。参数只影响之后建立的卡片。
4. 在项目栏保存 Pixelwork 状态，或从导出窗口选择资源格式。

图片保存在当前页面内存中。只有激活图片 API 并发起整体层生成时，重叠模板与提示词才通过 Runtime Bridge 发送给已选服务。

## 图片视图与分层素材

顶部一次选择一个图片视图：整体、地表、物件，或参考与派生菜单中的黑底参考、白底参考、Mask。Mask 由整体和物件 Alpha 派生，不能上传、删除或像素精修。各视图数量表示已有素材的卡片数。

“底图”“区域标注”“干净预览”仅控制编辑辅助显示。“此卡片参与地图输出”才决定卡片图片和区域是否进入 PNG、PSD 与 Godot；被排除的内容仍保存在编辑状态里。选择或悬停不会改变图片叠放顺序。

可靠的分层流程是：

- 上传独立地表和透明物件；或者上传同一物件的真实黑白底参考，再提取透明物件。
- “复制为地表草稿”只复制整图。草稿标记随状态保存；上传独立地表，或精修并点击“确认为独立地表”后，才参与分层合成。
- “由透明物件生成黑白参考”需要物件图片存在透明像素。不透明整图和完全相同的黑白参考不能冒充透明物件。
- 图片状态会标明上传、草稿、本地镜像补全、参考派生、提取或精修来源。

图片锁定作用于当前图片类型的全部卡片，涵盖上传、删除、精修和生成。异步任务提交时再次验证锁、原图片和文档版本；中途锁定再解锁，也会使旧结果失效。四边羽化影响卡片全部图片，因此相关图片被锁定时不能修改羽化。

## 区域绘制

区域是独立的矢量数据，分为遮挡扣除、碰撞、调整和顶层区域。每个区域记录所属卡片和创建时的图片视图。

- 默认列表与清空操作只针对当前卡片、当前图片视图、当前区域类别。
- “当前卡片的全部视图”会显示其他视图的参考区域。点击列表中的参考区域，跳到它所属的视图后编辑。
- 眼睛只隐藏辅助标注。遮挡扣除仍影响物件与 Mask；碰撞仍导出到 Godot；顶层仍从整体图裁出前景。
- 区域类别锁定作用于该类别的全部卡片。可以查看、选中锁定区域，不能创建、删除或清空它。
- 矩形点击两次；多边形点击添加顶点，Enter / C 完成；自由套索按住左键绘制，松开闭合。无效坐标、零面积和自交会给出提示。
- 区域在 SVG、命中检测、Alpha 扣除和 Godot 碰撞中共用闭合几何。

像素精修通过独立弹窗修改图片：保留画笔、橡皮、吸色、超级橡皮擦、框选移动、透明背景、撤销和恢复原图。弹窗内的快捷键不会操作地图区域。

## 导航与历史

| 操作 | 行为 |
| --- | --- |
| 中键 / 右键 / 空格 + 左键 | 临时平移，不添加区域顶点 |
| 平移按钮 | 切换持续平移；关闭后继续原绘制工具 |
| 画布滚轮 | 围绕鼠标缩放；属性面板滚轮只滚动面板 |
| 0、+ / -、H | 适配画布、缩放、切换卡片标签 |
| Esc | 依次取消草稿、取消区域选择、退出区域编辑 |
| Backspace / Delete | 有草稿时撤回顶点，否则删除可编辑的选中区域 |
| Ctrl / Cmd + Z | 先撤回草稿顶点，再撤销文档修改 |
| Shift + Ctrl / Cmd + Z | 重做文档修改 |

历史覆盖区域、图片替换与精修、羽化、卡片扩展和输出排除，最多保留 80 步；新操作会清空重做分支。切换卡片、视图、类别、工具、打开弹窗或失焦会取消草稿。历史不是保存文件的一部分。

## 生成队列

“生成队列”支持空整体卡片补全、批量物件提取，以及最多 64 块的自动向外扩展。并发为 1–4；可暂停、继续、取消、重试失败项和清除记录。

未激活 API 时，整体扩图使用确定性的本地镜像补全。物件提取在本地处理真实黑白参考。暂停让进行中的任务完成，取消则停止调度并丢弃未提交结果；已发出的外部请求可能继续在服务端完成。

内存保护按图片和历史的 RGBA 解码占用，加上生成临时画布预留估算，并非浏览器实际总内存读数。超过上限会在新任务启动前暂停；可调整阈值或在队列停止后释放历史。合成输出另有单边 30000 像素、总计 6400 万像素的限制。

## 保存、导出与恢复

| 格式 | 内容 |
| --- | --- |
| 当前图片视图 PNG | 当前图片类型的拼接结果，含羽化和适用的遮挡扣除 |
| 导出效果 PNG | 与 Godot 默认可见层一致的合成 |
| 全部图片层 PNG · ZIP | 所有已有图片视图、顶层、合成图和尺寸 / 原点清单 |
| 顶层区域 PNG | 顶层区域裁出的透明前景 |
| 分层 PSD | 按图片类型分层保存，参考和派生层也可检查 |
| Pixelwork 编辑状态 | 原始卡片素材、几何、区域、羽化、锁与显示偏好 |
| Godot 包 | PNG、`map_scene.tscn`、碰撞多边形、`regions.json`、读取脚本、项目文件及 `source_state.zip` |

“导出效果”使用实际导出合成算法：全部参与输出且有图片的卡片都具备独立地表和物件时，使用“地表 + 物件 + 顶层”；否则保留“整体 + 顶层”。单纯隐藏标注不会改变输出。

“打开状态 / Godot”支持 Pixelwork v1/v2、SceneMaker v5、新 Godot ZIP，以及旧 Godot 合成包。新包优先恢复完整编辑源；旧合成包只能恢复为一个地图块，并明确提示原卡片布局和羽化前素材无法恢复。帮助窗口也能打开带 JSON 清单和图片的完整资源文件夹。

仓库 Agent 新生成的 Godot 包也嵌入同批次 Pixelwork 源状态。更早的 Agent 包只有合成图片和场景时，加载器恢复图片并提示区域数据不足；要继续完整编辑，应打开同批次的 `pixelwork-state.zip`。

SceneMaker 的 ground 映射到 surface，整体图由旧视觉层合成，矩形碰撞转换为像素坐标；旧 foreground 烘焙入整体图，不猜测顶层区域。编辑器不会反向解析用户任意修改过的 Godot 场景脚本。

## API 与 Agent

默认整体层提示词面向纯 2D 横版过关背景：正交侧视立面，左右 / 上下为空间轴，禁止俯视、等距、纵深地面和 3D 渲染；保持原图笔触、配色及细节密度，不为每个卡片重复添加地面线或完整建筑。生成设置可“恢复横版侧视默认词”。旧状态中完全匹配旧版俯视默认词的文本自动迁移并提示，用户自定义文本保留。

外部生成后，服务端按模板尺寸回收结果，并逐像素保留模板中 Alpha 大于 0 的内容（含半透明边缘）；只填充完全透明处。明显不匹配的返回宽高比会报错，避免拉伸。此保护不保证新生成内容在视觉上完全无缝；未激活 API 的本地镜像补全不读取提示词。

生成设置只保留已有连接器实际支持的参数：服务选择、密钥、是否激活，以及唯一整体层提示词。Host 和 Model 由 Manifest 定义。密钥仅保存在 Runtime Bridge 进程内存或服务端环境变量中，页面只接收“已配置”状态，状态包和日志不包含密钥。

仓库 MCP / CLI 的 `map-stitcher` 能力仍通过 `workbench/manifest.json` 和共享 Runtime 执行。`compose` 本地拼接，`generate-layer` 仅支持整体层外部生成；生产产物写入 `outputs/<task-id>/`。具体输入见 [连接器契约](connector-contract.md)。

页面 WebMCP 另提供七个操作入口：读取摘要、切换视图、导入图片、生成图片、创建区域、导出、管理队列。它们与按钮、快捷键共用控制器，遵循相同锁与版本检查。页面内本地编辑不产生仓库级生产任务 ID。

## 验证

运行 `npm run test:map-stitcher`、`npm run typecheck`、`npm run lint`、`npm run build`。修改 Manifest 后运行 doctor；修改 Agent 桥接后运行 MCP 回归。

`node tests/map-stitcher/fixtures.mjs` 生成纯几何测试素材和兼容状态，写入不提交的 `work/map-ui-repair/fixtures/`。实际浏览器导出后的回读检查见 `tests/map-stitcher/verify-ui-exports.mjs`，验收记录见 [前端修复验证](MAP_STITCHER_REPAIR_VERIFICATION.md)。
