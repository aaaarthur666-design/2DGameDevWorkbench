# 论文方向与方法

> 状态：方向记录与进度（2026-11-10 重写，进度一节更新于 2026-11-14），以本文最新内容为准。目标会议 IEEE CoG 2027。
> 论文本身的主张、方法和实验草案见《[论文：先验证，再接续](论文-序列帧长动作生成.md)》，本文不重复。
> 实验规模、门槛与统计口径尚未讨论。

## 1. 当前方向（2026-11-10 确定）

以序列帧工具为基础，把它扩展成能生成**角色动作**和**交互物状态动画**的统一工具，再把图片局部编辑能力作为修正工具接进来。三者共用一个主张：

**先验证，再接续（Verify Before You Chain）。** 生成只从已验证的真实像素继续，未要求改变的内容必须保住。

| 内容 | 在论文中的位置 |
| --- | --- |
| 角色长动作 | 主实验。分段生成，每段从确认过的真实末帧继续 |
| 交互物状态动画 | 第二领域，小规模实验。A 状态图作首帧，生成过渡，验证过的真实末帧成为 B 状态图；多状态链 A→B→C 对应角色的多段接续 |
| 图片局部编辑 | "没通过就修"这一步里的修正工具集，占一组消融实验 |

## 3. 方向演变

| 版本 | 方向 | 放弃或调整的原因 |
| --- | --- | --- |
| 1 | 可验证的 Agent 场景共创系统（协议 + 系统） | 创新点多为工程保障；"Agent + 引擎测试"在 2026 年已拥挤 |
| 2 | 画面与碰撞一致性：推断 + 引擎验证 + 修复闭环 | 范围过宽，五件事挤在 8 页 |
| 3 | 收窄为"一致性问题的定义、度量与检测" | 只覆盖场景，体现不了整个项目 |
| 4 | 统一框架（合同、观察器、裁决）+ 序列帧与场景两个实例 | 两个实例没有共用的实验，框架容易写成功能罗列 |
| 5 | 序列帧长动作生成：先验证，再接续 | 只覆盖角色，项目里交互物和局部编辑的工作用不上 |
| 6（当前） | 第 5 版扩展到交互物状态动画，局部编辑作为修正工具集 | — |

### 6.1 场景的画面与碰撞一致性

- **问题**：画面上看起来能站的地方没有碰撞（假地面），或有碰撞但画面看不出能站（幽灵地面）。
- **定义**：感知可站面 H 以玩家标注为真值；物理可站面 Γ 是碰撞体上表面中上方有至少一个玩家身高空间的部分。两者按 x 方向每 4 像素采样，同列高度差不超过 τ（暂定 6 像素）视为对上；按长度加权，可达性只用于加权。
- **画面候选**：优先用分层地图和场景地图分层的结构，SAM 只作备选；物件能否站立的语义标签尚缺。
- **归档原型**（只读，保留在 `new-arch`）：[可站面检测](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/affordance.mjs)、[可达性](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/features/scene-composer/reachability.mjs)、[报告实现](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/lib/workbench/affordance-report.mjs)及[命令入口](https://github.com/aaaarthur666-design/2DGameDevWorkbench/blob/new-arch/scripts/affordance-report.mjs)。归档版本的原型测试通过，只在构造的测试场景上运行过；论文分支不提供此能力。
- **缺口**：未区分地表层与物件层；物件无语义标签；观察器不可插拔；可达性未经引擎验证。
- **相关工作**：[Investigating Human Priors for Playing Video Games](https://arxiv.org/pdf/1802.10217) · [Legible Ledges](https://bvbvf1.bib-bvb.de/vufind/PrimoRecord/cdi_uu_diva_oai_DiVA_org_uu_448883) · [Exploring Level Blending across Platformers via Paths and Affordances](https://arxiv.org/pdf/2009.06356) · [A Framework for Analysis of 2D Platformer Levels](https://eis.ucsc.edu/papers/smith-sandbox-08.pdf) · [Rhythm-based level generation](https://dl.acm.org/doi/10.1145/1536513.1536548) · [From Unstable to Playable (AIIDE-25)](https://arxiv.org/abs/2509.23787) · [Level Repair via MILP](https://ojs.aaai.org/index.php/AIIDE/article/view/7424) · [Image-to-Level](https://ojs.aaai.org/index.php/AIIDE/article/download/7429/7302/10897)

### 6.2 统一框架

第 4 版的三层说法（合同、观察器、裁决与绑定）仍可描述整个项目，适合两个以上模块都有硬实验结果后的系统长文（如 IEEE Transactions on Games）。当前论文只借用其中的规则：硬不变量一票否决、"未知"不算通过也不算失败、独立专家的具体矛盾不被后续复核清除、生成只从已确认的真实产物继续、人工采用不能放行技术检查失败的结果。
