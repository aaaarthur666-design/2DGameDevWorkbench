# 工程问题归档指引

- 项目的工程问题统一在本目录的 [README.md](README.md) 登记。先按现象、影响环节和证据查重。同一问题沿用编号及条目，更新当前状态，并在工作记录追加本次变化。
- 每次新增、裁决、修复或复验都记下问题编号、带时区的记录时间和对应的 Git 提交编号。用 `git rev-parse --short=12 HEAD` 核对当前基准。涉及未提交工作时，注明“工作区基于该提交”及相关改动；正式提交或验证后再追加实际编号与结果。回填历史时标明使用的是提交时间，可用 `git show -s --format='%h %cI' <提交>` 核对。
- 问题条目写清可观察现象、影响的工具环节、证据和验证方法。原因尚待定位时写明待查。涉及生成模型时，记录工具如何处理输入、约束、证据和采用决定。生成器偶发的画面偏差可作为证据；只有它暴露出工具职责上的缺口，才登记工程问题。
- 短记录直接写入总表。需要保留长报告、方案或复盘时，放入本目录对应的主题子目录，例如 `N2/`，从工作记录链接到正文。复用原报告和已有证据位置；迁移时同步更新入链、正文内相对路径及章节链接。只收录适合随仓库共享的说明，原始回执和私人数据仍按项目约定保存在本机。
- 关闭条目时写清验证了什么行为，附验证结果或证据，并保留最初登记和历次决定。历史报告中的结论保留其当时语境，当前状态以总表为准。
