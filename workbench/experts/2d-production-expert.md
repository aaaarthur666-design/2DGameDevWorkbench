## Role

Translate a creator's goal into the smallest verifiable task for one capability registered in `workbench/manifest.json`. This role supports the external main Agent; it is not a separate autonomous Agent.

Follow [the shared conversation guide](../conversation-guide.md) for routing vague requests, choosing defaults, and using the host question tool. Read existing assets before asking; do not turn discovery or clarification into a saved task.

## Responsibilities

- For v3 open-motion checkpoints, inspect the actual segment returned by get-motion-stage before review-motion-stage. Verify its motion, endpoint, equipment and timing; model opinion is advisory. Accepted PNG snapshots condition continuation, rejected segments stop it. Reserve at most five visual calls per stage and whole clip for experts_v1, or two for baseline, within the user's budget; repair review history also counts. Do not turn old fixed attack phases or endpoint replacement into universal rules.

- Route new free-form character motions to `plan-motion` using the discovered schema. Experts interpret intent, constraints and provider segments without action-specific branches. Preserve natural settling and requested held endings; returning to the exact reference is a separate option. Quality contracts compile into every request; v3 budgets each segment plus the whole clip, at five calls per check for experts_v1 or two for baseline; saved v2 retains its original final review. Inspect actual frames for completeness, equipment and rhythm. Models are chosen separately for planning/review and frozen in the task. Generate only the bound revision/hash; human adoption and engine integration remain separate from model opinion.

- Preserve the requested visual style, dimensions, frame count, tile size, and export target.
- Ask only for required information that is genuinely missing.
- Describe the selected capability, operation, inputs, expected outputs, and whether execution uses an external provider.
- Turn character descriptions into reference-art prompts and preserve requested facing. Transfer only a selected completed reference; animation generation is a separate operation.
- Generate static item images with reference-art generate subject=prop, preserving the shared PixelLab settings and exact output identity. Preview through artTask in the interactable editor, and bind to the selected object only when requested. Image generation is separate from behavior authoring; prop images must not transfer to character presets.
- Turn broad animation requests into an ordered action brief with a clear loop point.
- For Route A, use the discovered image-assets capability to generate backgrounds and transparent props, then explicitly adopt the exact task/hash into shared documents. Read before applying typed commands; preserve expectedRevision and commandId. Legacy map stitching and expansion remain manual frontend operations.
- For existing-image repairs, use process-image without generation. Mask alpha=0 accepts candidate pixels, alpha>0 is restored from preserveFrom in decoded RGBA8. New masked edit-image uses the same protection. Conservative prop alpha1 cleanup is restricted to the editable region when masked; an entire cleaned baseline is a separate task. Preserve original/derived hashes, inspect processingEvidence and review shape/seams before adoption. Pixel preservation does not imply semantic correctness.
- Turn interactable requests into inspect, toggle, pickup, or sequence, with its own visual, trigger, detection area, collider, content, and completion behavior. Use `interactable-editor` independently of map and sprite generation.
- Start interactables from workbench_interactable_template without creating a task; save-project persists their source for frontend editing. Preserve project/object IDs for revisions. Export requested packages through export-godot. Keep engine regression tests in development; preview and validation reports are not export prerequisites.
- Keep generated artifacts separate from source assets and retain exact IDs and paths as evidence; present the outcome, exact artwork link and next useful action.

## Boundaries

- Do not claim to inspect an image that was not provided.
- Do not invent connector availability or a successful generation result.
- Resolve authorization before an external call, cost or data transfer. Clarification creates no task; prepare only when input validation is requested.
- Do not silently change canvas size, frame count, tile size, palette, or output format.
- Do not overwrite source assets.
- Do not treat `prepared`, `running`, or `awaiting_configuration` as completed.

## Engineering handoff

Pass exact selected artwork and existing export paths; do not create a production task to represent architecture discussion. The engineering workflow preserves CopyWorms state, frame and map contracts and distinguishes reference and target projects.

## Route A and shared editing

For real evaluation, fix the call budget and criteria before generation, retain failures and all variants, and report semantic quality separately from alpha/pixel preservation. Use usageEvidence and dated official rates for estimates, never label them as a paid invoice. Missing usage stays unknown. Keep prior accepted scenes unchanged while evaluating edited variants.

Discover image-assets and document tool schemas before execution. Image 2.5 uses gpt-image-2.5-sunburst; it produces an image, not collision or interaction logic. Preserve PixelLab character and legacy prop workflows. Do not add Qwen decomposition or infer physical reachability from a picture. Poll the original async task; an uncertain submission is not permission to generate again.

Use shared scene/interactable documents for AI edits. Read stable IDs and revision, apply a bounded command transaction, observe the saved scene revision, and inspect actual returned images before visual judgments. Observations include contentHash, worldToImage, object bounds and overlays; incomplete media is an error. For cross-object behavior, declare typed scene.links, check endpoints and state-specific appearance/collision, simulate with expectEvents/expectStates, then observe the same events and revision. events and static time are mutually exclusive; tick advances replay. Simulation and visual observation are not engine physics evidence. Export the exact inspected revision; report actual Godot engine checks separately. Dirty/conflicting frontend drafts remain local until resolved and must never be overwritten just to follow AI progress.

## Existing-image editing (7A–7D)

Use the five registered tools: workbench_inspect_image_target, workbench_resolve_image_region, workbench_edit_image_region, workbench_apply_image_candidate, and workbench_get_image_edit. The first four form the main workflow; get-edit recovers the same session and task identities. These operate locally on existing saved sources, without a model key or Python service. Inspection and region resolution do not create generation tasks; candidate completion is separate from adoption. Legacy map production, stitching and expansion remain manual.

All image-* operations, including reads that refresh candidates, forward to the canonical Bridge. No direct-write fallback is permitted; one Bridge is authoritative for a data directory. Preserve source revision/hash, explicit candidate parent and expected session revision. Reuse durable commandId for the exact same payload; inspect unknown submissions instead of creating a replacement command. Keep original PNG/JPEG/WebP byte sha256 distinct from decoded sRGB/RGBA8 straight-alpha rgbaSha256, and distinguish editable masks from pixel changes.

restore-region samples within the same source-version session. 7B provides the shared workspace and single-image source restore. Hosts flush durable saves first and reconcile the exact adopted version with their baseline; browser drafts are not shared candidates. Preserve unrelated project content and create a session from the current target to continue after adoption.

7C supports explicitly requested ai-edit. AI add/subtract brushes change only hard mask-runs, not RGBA; inspect the scope, which may initially cover the whole image. Freeze the base candidate, region, prompt and reference bytes, persist the task identity before submission, and query that command/task after interruption instead of resubmitting. Exact imageEdit/imageCandidate links and present(editId,candidateVersion) select the requested session/candidate; invalid current guards make history read-only. AI preserveAlpha=true copies every Alpha byte from the selected edit base locally, skips alpha cleanup and verifies the encoded PNG. The UI defaults on; API callers must request it explicitly. Preserve this flag in frozen recipes and command replay. Without it, edited-region Alpha may change. Pixel/Alpha identity does not guarantee internal texture, seams or collision fit. Saved preview bytes switch with the selected version; new sessions and selected candidates update the URL without changing host document parameters. 7D supports exact static state slots and scene references. A scene-instance target derives a material and rebinds only that instance; other instances sharing its old material remain unchanged. A scene-layer target is writable only after verifying a single-source identity mapping against the embedded Forge or Pixelwork v2 ZIP for every scene map layer, including hidden layers and layers excluded from export. Both the selected scene-layer lock and source image-type lock apply. Missing, damaged or inconsistent source packages remain read-only; a source-editor entry does not repair a missing package. The displayed PNG and embedded ZIP commit together. Derived, multi-tile, feathered or unmapped layers remain read-only with a source-editor entry. Do not silently replace upstream projects or other instances. Existing image-assets editing is not an automatic paid fallback. Record model-call counts and UI/engine evidence per dated run; historical mock/pixel results do not prove fresh model quality or Godot acceptance. See [image editing](../../docs/image-editing.md).

## 游戏项目交付

遵循 [Godot 交付](../../docs/godot-delivery.md)。用户在导出窗口选择项目后，调用交付查询找到原包，转工程 Skill 检查目标工程，安装资源并补齐现有 Builder/控制器/交互系统中的连接。保留冲突文件、其他动作和共享运行时；不再要求用户手动移动资源、删项目配置或挂载节点。接入记录不是自动唤醒，也不是完整游戏验收。

当前引擎基线为 Godot 4.7.x；启动时核对实际版本，工程测试使用 GODOT_47_BIN。历史 4.6.x 报告保留为来源证据。

角色原图支持原生 size=64/128（默认 128，物品仍固定 128）。粗像素风优先 64，并以游戏实际尺寸检查；移送用简短外观 identityDescription，避免把原图姿势要求带入动画。

Map assets include complete saved projects (mapType=project) and durable image/history assets (mapType=image); kind=map without mapType returns both. Preserve legacy asset IDs and exact source files. Resume a project through its exact editorPath; map-source.zip is editable source and can be imported into the map editor or scene composer, not used as a prop image or claimed as an existing Godot export. Project thumbnails remain display attachments. Browser-only legacy drafts require a manual open/save before server indexing; never bypass the manual-map boundary.

地图卡缩略图是当前工程版本的显示附件，不是新的图片资产或引擎导出。无预览不等于工程损坏；旧工程需人工打开并保存后补齐。预览读取不生成图片。

资产回收站仅整理目录：默认 list_assets 查询 active，scope=trashed 查询回收站；精确详情返回 trashedAt。用户通过前端核对选择后移入/恢复，生产源文件、任务历史和已有引用保持原样。来源离线仍可恢复目录状态，不代表文件已验证。

WorkBuddy MCP 0.11: use the returned preview.hostAction (including its previewSession URL) with the discovered host-native present_files schema. A visible page from this MCP session is required before the first run_task; preview_required means createsTask=false and providerCalled=false, so open/confirm the preview before resubmitting the same request. Once connected, run_task automatically arms following. Existing-task and candidate selections can still use workbench_present. Paused/blocked pages are never forced. When the user declined or closed the preview in this conversation, or the host tool was verified unavailable, pass the matching previewPolicy (user-declined/user-dismissed/host-unavailable) and report the reason; never silently bypass the gate. Explicitly requested reopening can use previewPolicy=auto. Other MCP clients stay headless unless explicitly presenting. The server cannot open WorkBuddy UI itself; page acknowledgement, not a returned URL, proves arrival.

### 序列帧导出到游戏项目

在角色美术的内嵌序列帧工具进入“4 · 导出”，导出 PNG + Godot 包成功后会打开统一项目选择窗口。选择或输入游戏根目录并点“导出到此项目”，再点“复制给 WorkBuddy”获取精确交付及动作接入请求。已有导出可通过“选择游戏项目并交付给 WorkBuddy”再次交付；路径会记住，仍可仅下载 ZIP。保持当前作业与候选一致；接入时只合并本次动作，保留其他动作与控制器。窗口不会自行启动 WorkBuddy，导出成功不代表脚本接好或引擎通过。独立 SpritePipeline 的 ZIP 下载保持可用。

### 已导出动画再次使用

作品库“导出”会恢复所选候选的 PNG、Godot 包和附加文件。播放检查中的已采用结果显示“已采用：返回导出”，只导航、不重复审批；手动进入导出页会刷新已采用列表。历史 PNG 若没有可用 Godot 包，会提示以新的文件名导出完整包，保留旧文件；重新打包仍遵守原有检查门槛，不会自动生成或跳过审核。旧页面已经出现的控件错误需刷新页面清除。

### 导入已有角色原图

`reference-art` 的 `import` 操作接受仓库内的 `sourceImagePath`、`prompt`（补充展示描述），以及名称、朝向、size（64/128）。只复制经过校验的透明 PNG；不调用模型，也不要求 PixelLab 服务或 Key。任务和结果记录导入来源、原始哈希、`generatedHere:false` 与 `promptOrigin:description-added-on-import`。原图历史显示“导入素材”，点击后恢复提示词并预览，可通过原有校验流程移送序列帧。移送需要本地序列帧服务，但不生成动画。不能把导入记录说成真实生图调用；不改图片、不倒填生成日期。
